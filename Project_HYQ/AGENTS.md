# Codex 协作规则

## 执行前确认

在用户提出任何需求后，Codex 必须先和用户讨论方案，不能直接修改文件、运行会改变项目状态的命令、安装依赖、创建提交、推送代码或执行方案。

允许在形成方案前进行只读操作，例如查看文件、搜索代码、检查当前状态；但在真正执行修改前，必须等待用户明确确认。

只有当用户明确说出“执行”“按这个方案做”“开始实现”“可以改”等确认语句后，Codex 才能开始执行方案。

如果需求不明确，Codex 应先提出澄清问题或给出可选方案，而不是自行假设并执行。

## 代码风格一致性

执行代码修改时，Codex 必须优先遵循原项目已有的代码风格、目录结构、命名方式、格式化习惯、技术栈和现有抽象方式。除非用户明确要求重构或改变风格，否则不要引入与原项目明显不一致的新写法、新框架或新组织方式。
